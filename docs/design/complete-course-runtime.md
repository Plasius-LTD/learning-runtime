# Complete course runtime delivery

Tracked Task #1 belongs to the complete Junior Coder programme's Feature #1704 and
Story #2236 in the studio repository. Inherited rollout is
`learning.junior-coder.workspace.enabled`; the course host additionally composes
`learning.junior-coder.courses-v2.enabled`, disabled until course acceptance passes.

The runtime is reusable execution infrastructure, not a course or completion
authority. Deliver one shared implementation for browser workers and server
assessors: typed maze programs; isolated JavaScript state/update projects; and
documented robot simulator languages. Use module-specific scenarios and structured
frames that support text, keyboard, step/pause and reduced-motion presentations.

Start with Robot Maze: closed visual instructions forward/left/right/collect,
repeat, if-clear and named routine calls. Validate the entire input before running;
cap source at 16,000 characters, nodes at 256, nested structures at 12, routines at
16, executions at 512 and calls at 16. Worlds are at most 20 by 20 with bounded
wall/explorer sets. Reaching the pad after all explorers have been collected ends
the rescue immediately. This is an explicit game rule, not a hidden code shortcut.

Every runtime requires reference-program, starter, plausible-wrong, edge, budget
and safety tests. Project data is ephemeral; the host owns bounded private saves.
No raw source, answers or identifiers enter metrics. Work runs synchronously within
explicit local budgets or in a disposable isolated session, with no retry loops or
network waits. There are no production cloud resources or secrets in this package.

The following runtime work remains after the maze: isolated JavaScript sessions,
full game state adapters, robot state machines and web-project reducers. This
document and package scaffold do not establish completion of any full course.
